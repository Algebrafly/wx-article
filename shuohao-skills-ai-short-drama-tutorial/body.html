我最近在啃一套开源工具，叫 shuohao-skills。

它是给 AI 短剧（包括漫剧）做**全流程生产**的 skill 集合——从一本小说，到直接丢给视频生成管线的分镜提示词包，七个环节全部覆盖。

最值钱的不是提示词模板，是 50+ 道确定性质量门：大纲 14 道、剧本 10 道、分镜 18 道，全部由 Node.js 脚本执行，不靠 AI 自觉。

零依赖、零 API key、Apache 2.0 开源。只要 Node ≥ 18 和一个能读 SKILL.md 的 Agent（Claude Code、Codex、Trae 都行）。

这篇是完整使用教程——我实际跑通后的经验整理，不是 README 翻译。

01

环境准备

先列清楚前置条件，免得装到一半报错。

必需的：

· Node.js ≥ 18（只用标准库，不用 npm install）

· 一个能读 SKILL.md 的 Agent（Claude Code、Codex、Trae 都兼容）

· 模型额度（用当前会话的，不需要额外 API key）

唯一例外：只有 character-refs（真出角色参考图的 skill）需要出图模型，四选一：ComfyUI（Qwen Image）、codex 内置出图、OpenAI Images API、自定义命令。

安装就是三行命令：

git clone https://github.com/eternityspring/shuohao-skills.git
cd shuohao-skills
./scripts/install.sh

安装脚本会自动检测 Claude Code 和 Codex，创建软链接——之后 git pull 立刻生效，不用重装。只装某一个 skill 也行：

./scripts/install.sh novel-outline   // 只装大纲 skill
./scripts/install.sh --uninstall   // 取消软链

国内直连 GitHub 不通的话，走 gh-proxy.com 镜像下载压缩包即可。

02

7 个 Skill + 完整流水线

整个流水线分成 六个制作阶段 + 一个独立出图 skill：

小说原文 → novel-outline（改编大纲）
    → novel-characters（角色设定） + novel-art（美术设定） + novel-script（剧本）
    → novel-staging（开场站位）
    → novel-storyboard（分镜）
    → 视频投产包（可直接喂给 H3、Seedance 等视频模型）

character-refs 可以独立用——它是唯一真出图的 skill，给任何故事的角色出参考图，不依赖小说原文。

五个核心 skill 的接力关系：

Skill 产出 JSON 回答什么问题
novel-outline outline.json 什么结构、多少集
novel-characters cast.json 谁、长什么样
novel-art art.json 哪里、什么场景
novel-script script.json 演什么戏、节拍台词
novel-storyboard storyboard.json 怎么拍、镜头提示词

五份 JSON 各自独立可跑，改完喂回各自的 validate/render，互不干扰。

03

逐环节使用教程

下面按实际跑的顺序讲。每个环节我只讲**最关键的触发指令、输入输出、质量门怎么跑**——完整细节看 SKILL.md。

▎ 第一步：novel-outline · 改编大纲

触发指令（跟 Agent 说）：

把这本《XXX》改编成 30 集 × 2 分钟的短剧大纲，题材是都市逆袭

Agent 会按 SKILL.md 的 Step 0 到 Step 7 执行，自动跑 14 道质量门校验。

14 道质量门（脚本自动检查）：

· 主角组 1–5 人、重要配角 ≤ 10、功能性角色 ≤ 10

· 主场景不超上限（随集数动态，60 集 → 10 个）

· 叙事道具 ≤ 8 件

· 爽点间隔 ≤ 3 集无真空

· 第 1 集有钩子、大爆点不压最后一集

· 三人同框必须有拆解方案

· 所有引用完整、无失业角色、无空转场景

· 梗概是叙述体，出现对白直接拦

实测踩坑：爽点间隔那个门是真拦得住——我第一次写的大纲 7 集连续憋屈，validate 直接报错。按"当众、当场、当脸打脸"重写后，爽感达标集数从 6 集拉到 20 集。

体检模式（贴已有大纲进来诊断）：

node skills/novel-outline/scripts/novel-outline.mjs checkup outline.json

▎ 第二步：character-refs · 真出角色参考图

这是仓库里唯一真出图的 skill。其余 skill 只交提示词，因为出图那一刻才能决定模型和画风。

核心机制：一张锚点，全组参考——先出正面全身锚点（文生图），大头照、90° 侧面、背面、细节图都只参考这张锚点，互不参考，所以任何一张出坏了单独重出就行，不会连锁。

前置配置（第一次用，一次搞定）：

node skills/character-refs/scripts/character-refs.mjs config --show
node skills/character-refs/scripts/character-refs.mjs config --model codex --confirm-anchor yes

四个模型选项：

· qwen（ComfyUI，每张 25–45 秒，不吃订阅额度）

· codex（GPT 内置，吃订阅额度，每张 80–160 秒）

· openai（GPT Image 2，按量计费）

· custom（自己写的出图命令）

触发指令：

给我出一个 28 岁都市职场女性的角色参考图，黑长直、白色职业装、带金丝眼镜

出图分档：

· Tier 1：只有正面全身锚点

· Tier 2（默认）：正面全身 + 大头照 + 90° 侧面 + 背面

· Tier 3：再加细节图（头发、领口、袖口、鞋，最多 8 张）

· Tier 4：45° 大头照（默认不出）

实测踩坑：只给正面全身，服装和背影都对，但脸会走样。加一张大头照，脸最接近。锚点是全组的根，强烈建议配置"锚点确认 = yes"，出完锚点先停，人看过再继续。

▎ 第三步：novel-storyboard · 出分镜 + 投产包

分镜是管线里第一个直接面对视频模型的层。核心规则：镜头是生成的，多切一镜成本几乎为零，所以上限只有一个——视频模型单段生成的时长（默认 15 秒）。

三层结构：

· 段（一次视频生成，≤ 15 秒，不跨场）

· 分镜（段内 2–5 秒的剪切，认领剧本节拍）

· 分镜图（每切一张关键帧，主分镜图钉 0.00 秒，子分镜图钉切点时刻）

关键机制：镜头认领节拍——每个镜头声明它覆盖剧本某场的哪几个连续节拍，镜头不许跨场次。剧本改了重跑 validate，失效的镜头当场点名。

18 道质量门（部分）：

· 节拍全覆盖（恰好一次、按顺序、连续）

· 段 0 < 总秒 ≤ 15，每切 2–5 秒

· 台词装得进分镜（逐镜检查，不是拍脑袋）

· 每集总时长在剧本目标 ±15% 内

· 视频提示词不含角色名（用 C01、S01 代替）

· H3 对齐指令由分镜结构推导，逐字对账

· 认领台词逐字进 `[Chinese] ...` 块

export 一键出投产包：

node skills/novel-storyboard/scripts/novel-storyboard.mjs export storyboard.json --frames ./storyboard   // H3 投产包
node skills/novel-storyboard/scripts/novel-storyboard.mjs export storyboard.json --protocol seedance   // Seedance 投产包

产出是 `manifest.json` + `E01-01/`、`E01-02/` 每段一个文件夹，里面有 prompt.md（完整视频提示词）和 f1..fN.png（分镜图，下游出完放进来）。

实测踩坑：把段文件夹塞进 `segments/` 目录，报告里的图全变成"未生成"占位。分镜报告里的图走相对路径 `<段号>/f<切序>.png`，段文件夹必须跟报告 HTML 同级。

04

质量门：为什么它是整套工具的核心

shuohao-skills 和市面上其他 prompt 模板最大的区别——

50+ 道质量门，全部由代码执行，不靠 AI 自觉。

AI 写东西天生凑活——大纲爽点间隔 5 集也敢交、分镜切 7 秒也不提醒、台词塞进镜头超时没反应。

shuohao-skills 的做法是：模型写完 → Node.js 脚本跑 validate → 过了才往下走，没过逐条报错、改完重跑。

质量门分布：

Skill 质量门数量 自测断言数
novel-outline 14 道 249
novel-characters — —
novel-art 10 道 —
novel-script 10 道 —
novel-storyboard 18 道 336

* novel-characters、novel-staging、character-refs 各自有质量门，详细数量见对应 SKILL.md。

每道门都有击穿用例——novel-outline 的 14 道门对应 249 个自测断言，novel-storyboard 的 18 道门对应 336 个断言。跑一遍就知道它真的会拦。

改完脚本先跑自测：

for f in skills/*/scripts/selftest.mjs; do node "$f"; done

跑一次 1 秒，不调模型、不花额度。比等 CI 快得多。

05

工作目录约定 + 五个报告合成

跑完整流水线后会产出大量 JSON、MD、HTML——别平铺在根目录，按六个 skill 各建一个目录归档：

<demo>/
├── outline/       ← novel-outline 产出
├── characters/  ← novel-characters 产出
├── art/          ← novel-art 产出
├── script/      ← novel-script 产出
├── staging/     ← novel-staging 产出
├── storyboard/  ← novel-storyboard 产出 + 投产包
├── docs/          ← 自己写的使用说明、PR 草稿
└── scripts/      ← 跑管线的辅助脚本

想把五个阶段的报告合成一张单页（左侧导航切换，支持数字键 1–5 切面板，Cmd+F 全局搜索）：

node scripts/report.mjs --from <demo目录> --out report.html

它是组装器，不侵入任何 skill——调各自的 render 拿产物再拼装，处理了样式串味、脚本串味、图片路径三个坑。

06

实测踩坑合集（每条值回票价）

这些坑不是 shuohao-skills 文档里写的，是我和其他跑过的人实际踩出来的。

① AI 画面写字必乱码。招牌、传单、投屏、弹幕全部留空后期贴字。AI 写字 10 次 9 次乱码，这是行业共识。

② 语速快是台词密度问题不是配音问题。4.5 字/秒是硬上限，超了拆镜不砍字。一个字不用砍，只需重新分秒拆镜。

③ 角色锚点句换一个字就换脸。锚点确认过的正面全身图，之后所有派生图都只参考这一张。锚点改了，派生图全部标过期。

④ 爽点间隔超过 3 集观众就划走。大纲质量门拦得住，剧本改之前也建议自己扫一眼。连续憋屈超过 1 集就不行。

⑤ 段文件夹别多套一层目录。分镜报告里的图走相对路径 <段号>/f<切序>.png，段文件夹必须跟报告 HTML 同级，多套一层报告不会报错，但图全变成"未生成"占位。

⑥ GitHub 直连不通。走 gh-proxy.com 镜像下载压缩包，或者用 curl 的代理。

⑦ 国产短剧建议用 Tier 3 细节图。只给正脸大头照不够——领口、发饰、袖口、鞋这些细节，才是让同一个角色在不同镜头里认出来的关键。

07

总结

shuohao-skills 的价值，我觉得不是"AI 做短剧"——那市面上一大堆。

它真正解决的问题是：AI 天生凑活，人类没精力逐镜盯质量。

50+ 道质量门把"逐镜盯"这件事自动化了——模型写完 → 代码校验 → 过了才往下走，没过逐条报错。

七块 JSON 接力、各自独立可跑、改完喂回 validate——这是一条可以**批量生产 AI 短剧**的管线，不是单部剧的 prompt 模板。

零依赖、零 API key、Apache 2.0 开源。

如果你也在折腾 AI 短剧，去试试。
